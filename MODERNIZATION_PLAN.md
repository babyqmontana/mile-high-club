## 2. Этапы реализации

Каждый этап — отдельная ветка и отдельный коммит (или PR) с чекпоинтом. Следующий этап не начинается, пока у предыдущего есть критические ошибки.

### Этап 0 — Подготовка (после D1, D6)
* Импорт исходников из бандла (D1).
* `tests/smoke.mjs` на Playwright: демо-сервер на свободном порту → все 12 маршрутов × (1440, 768, 390) → нет ошибок консоли и горизонтального скролла → сценарии: бронь (код брони появляется в `#me`), заказ в номер, заявка до шага 3, вход демо-админа и подтверждение брони (статус номера меняется на «Забронирован»).
* Эталонные скриншоты «до».

### Этап A — Глобальная визуальная система
* Токены из DESIGN_SYSTEM §2, §5, §7 добавляются в `app.css`; старые переменные остаются как алиасы.
* `--floor-tint` по страницам, зерно, отказ от бесконечной анимации `.eyebrow`.
* Шрифты: 7 начертаний, preload.
* **Проверка:** визуальный дифф скриншотов (ожидаемые изменения: фон и заголовки), smoke зелёный.

### Этап B — Навигация и переходы
* Переход «лифт» через View Transitions с fallback; направление по этажам.
* Drawer → панель лифта (Esc, focus trap); индикатор этажа в шапке.
* `modal()`: focus trap, `inert`, анимация.
* Лоадер: только первый визит, без ожидания `hero3d`.
* **Проверка:** клавиатурная навигация по всем маршрутам; Esc в drawer, modal, sheet; reduced motion → crossfade.

### Этап C — Основные страницы
* Главная: табло split-flap, билеты событий, шахта лифта, бирки пакетов.
* Отдых: точечные обновления вместо перерисовки, «Сутки отеля».
* Le Ciel: меню-карта, FLIP в корзину.
* Сигары: исправление подписи, фильтр.
* **Проверка:** данные на табло совпадают с `/api/public`; изменение статуса номера в панели → табло обновляется через SSE без перезагрузки.

### Этап D — Сложные интерактивные компоненты
* Фильтр номеров над башней, сравнение типов.
* Ползунок «Сутки отеля» (drag, клавиатура, `aria-valuetext`).
* Shared-element переходы: анкета сотрудника, обложка журнала.
* **Проверка:** фильтры работают только на реальных данных; пустые результаты показывают состояние empty с действием «сбросить».

### Этап E — 3D и WebGL
* Пролёт камеры к этажу в башне; пульс выбранного окна.
* Менеджер GPU: единый «активный» цикл, `dispose()` и `loseContext()` при пересоздании hero и при долгом уходе со страницы (> 60 с) для манекена.
* Fallback без WebGL: статичная картинка или текущий текст + кнопки лифта (сейчас — только текст).
* (P3) дым над сигарой.
* **Проверка:** память GPU стабильна после 10 переключений день/ночь (Chrome Task Manager / `renderer.info`); FPS ≥ 50 на 4× CPU throttle при открытой башне; без WebGL все сценарии выполнимы.

### Этап F — Микроанимации
* Магнитная CTA атриума и FAB (`pointer: fine`), перещёлкивание цифр, вход ключ-карты в замок, контекстные CSS-курсоры над сценами.
* **Проверка:** ни одна анимация не трогает layout-свойства (Performance panel: нет Layout в кадрах анимации).

### Этап G — Мобильная версия
* Bottom sheet ≤640 с жестом закрытия, лента этажей в лифте, шапка из 3 иконок, `svh`.
* **Проверка:** 390×844 и 360×740, touch-эмуляция, все цели ≥44 px, нет горизонтального скролла.

### Этап H — Оптимизация и исправления
* `compression`, версия ассетов (D2), `srcset` для атриума (1440/2160/2880 webp), `fetchpriority="high"` для hero.
* Lighthouse mobile до/после; цели: LCP ≤ 2,5 с (Slow 4G-профиль), CLS ≤ 0,05, INP ≤ 200 мс, TBT ≤ 300 мс.
* Финальный отчёт (этап 10).

## 4. Что намеренно НЕ делаем

* Не переписываем на React, Next.js или с использованием сборщика.
* Не меняем `core.js`, API, схему данных, авторизацию.
* Не добавляем фиктивные данные: «онлайн-персонал», отзывы, рейтинги, «осталось 2 номера» сверх реальных статусов.
* Не вводим глобальный кастомный курсор и scroll-hijacking.
* Не удаляем `tower3d.js` и `lift.js` без решения владельца.

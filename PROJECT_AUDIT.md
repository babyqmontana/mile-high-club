## 0. Состояние репозитория — важно

В репозитории `babyqmontana/mile-high-club` на ветке `main` лежит **только один файл** — `mile-high-club.bundle` (git bundle, 4,1 МБ). Исходники находятся внутри бандла (один коммит `5561794 «Mile High Club: сайт отеля, панель персонала и Discord-бот»`, 56 файлов).

Для аудита бандл был распакован во временную папку; рабочее дерево репозитория не трогалось.

**Решение принято (вариант A):** исходники импортированы merge-коммитом с сохранением истории коммита `5561794`, бандл оставлен как архив.

| Вариант | Что происходит | Риск |
|---|---|---|
| **A (рекомендую)** | Распаковать бандл в корень репозитория отдельным коммитом «import sources from bundle», бандл удалить (или оставить как архив). Дальше — обычные коммиты по этапам. | Минимальный. История бандла сохраняется через `git fetch` из бандла, если нужно. |

## 2. Архитектура

```
Browser (SPA, hash routes)                          Node process
┌────────────────────────────────┐                 ┌──────────────────────────────────┐
│ main.js  — shell, роутинг,     │  fetch /api/*   │ index.js — Express, сессии,      │
│            рендер всех страниц │ ─────────────▶ │            OAuth, upload, SSE    │
│ ui.js    — state S, modal,     │                 │   │                              │
│            sheet, toast, reveal│  EventSource    │   ▼                              │
│ api.js   — fetch / DEMO-режим  │ ◀───────────── │ core.js — ВСЯ бизнес-логика,     │
│ admin.js — панель персонала    │   /api/stream   │           роутер API, валидация  │
│ *3d.js   — three.js сцены      │                 │   │            ▲ hooks           │
│ wx/sound/deck/achievements     │                 │   ▼            │                 │
└────────────────────────────────┘                 │ store.js (SQLite)   bot.js (Discord)│
       ▲  в DEMO core.js исполняется                └──────────────────────────────────┘
       └─ прямо в браузере (localStorage)
```

Ключевая особенность: **`public/js/core.js` изоморфный** — один и тот же файл импортирует сервер (`server/index.js`) и браузер (демо-режим `window.MHC_DEMO`, а также константы/хелперы `venueState`, `weatherNow`, `ROOM_STATUS` в `main.js`). Любое изменение в нём меняет и сервер, и клиент.

Рендеринг: каждая страница — функция `renderX()` в `main.js`, строит HTML строкой через `innerHTML`; все секции существуют одновременно (`<section class="view" data-view="…">`), активная получает `.on`. Данные: `S.pub` (публичные), `S.me`, `S.items`, `S.admin`. Изменения от сервера приходят списком коллекций через SSE → `onChange()` перезагружает `/public` и перерисовывает текущую страницу.

SSR и hydration **не используются**.

## 4. API (`core.js`)

Публичные: `GET /public`, `GET /me`, `GET /me/items`, `POST /bookings`, `POST /orders`, `POST /tickets`, `POST /tickets/:id/recheck|mode|messages`.
Персонал (mod+): `GET /admin/all`, `POST /admin/rooms/:id/status`, `POST /admin/bookings/:id/action` (confirm/checkin/checkout/cancel), `POST /admin/orders/:id/status`, `POST /admin/tickets/:id/close`, `POST /admin/events/sync`, `POST /admin/discord/post`, `PUT|DELETE /admin/:col/:id` (по таблице `EDITABLE`).
Только admin: `PUT|POST|DELETE /admin/rooms`, `POST|DELETE /admin/floors`, `POST /admin/discord/setup`, `POST /admin/reset` (требует слово «СБРОСИТЬ»).
Вне core: `/auth/config`, `/auth/discord`, `/auth/callback`, `/auth/demo`, `/auth/logout`, `POST /api/admin/upload`, `GET /api/stream`.

`settings` (main), `types`, `rooms`, `venues` (+schedule), `menu`, `cigars`, `depts` (+items, model), `team`, `offers`, `faq`, `issues` (+pages), `events`, `media`, `bookings`, `orders`, `tickets` (+messages), `log`, `meta`. ## 6. Авторизация и права

* Сессия — HMAC-подписанная cookie `mhc_s` (HttpOnly, SameSite=Lax, Secure при https), 7 дней.
* Вход — Discord OAuth2 (`identify guilds.members.read`), `state` в cookie. Роль переопределяется через бота раз в 10 минут.
* Роли `guest < mod < admin`, проверка `need(user, role)` в каждом маршруте core.
* Гость без входа владеет своими бронями по `X-Guest-Key` (случайный ключ в localStorage).
* Rate-limit: 40 не-GET запросов в минуту на IP (кроме `/api/admin`).
* Демо-вход только при `DEMO_LOGIN=true`.

## 12. Где можно добавить интерактивность без изменения бизнес-логики

Все пункты ниже используют только уже существующие данные `S.pub` / `S.items` и существующие эндпоинты.

* **Главная:** «табло отеля» (split-flap) из реальных `rooms`/`venues`/`events` вместо одинаковых плиток; вертикальная «шахта лифта» как навигация по разделам, где этажи — реальные этажи площадок из `venue.floor`.
* **Номера:** фильтр по типу, вместимости и цене поверх башни (данные `types`/`rooms`), камера летит к этажу; сравнение типов.
* **Отдых:** общая шкала «24 часа отеля» со всеми площадками на одной оси (сейчас — отдельная шкала у каждой карточки), перетаскиваемый «ползунок времени», который показывает, что будет открыто в выбранный час (через существующую `venueState`/`inSpan`).
* **Le Ciel:** анимация «блюдо летит в корзину» (FLIP), счётчик в FAB.
* **Хьюмидор:** фильтр по крепости и происхождению (данные `cigars`).
* **Журнал:** переход «обложка → книга» через View Transitions (Chromium и Safari; в остальных браузерах обычный переход).
* **Персонал:** карточки команды — раскрытие в модалку через shared-element переход.
* **Заявка:** живой индикатор «персонал онлайн» **не добавлять** — таких данных нет (это была бы фикция).

## 13. Ограничения для следующих этапов

* Без сборщика: новые библиотеки подключаются только как вендоренные ES-модули (как three.js), с фиксированной версией. Сборщик не вводим без отдельного согласования.
* Добавлять зависимости в `dependencies` только для сервера (например, `compression`) и только после согласования.
* Каждый этап: smoke-прогон всех маршрутов (десктоп и мобильный), консоль без ошибок, бронь, заказ, заявка и панель в демо-режиме.
